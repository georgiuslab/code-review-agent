# Code Review Agent

LLM-ზე დაფუძნებული აგენტი, რომელიც პროგრამისტს ეხმარება საკუთარი repository-ის
მიმოხილვაში: ბუნებრივი ენით დასმულ კითხვებზე ის თავად ამოწმებს
პროექტის ფაილებს და პასუხობს მის საფუძველზე.

## რა პრობლემას ჭრის და ვისთვის

დამწყები პროგრამისტები, რომლებიც ახალ ან საკუთარ დავიწყებულ
პროექტს ათვალიერებენ (მაგ. პორტფოლიო-პროექტი), ხშირად კარგავენ დროს
სტრუქტურისა და ტექნოლოგიების გასარკვევად. აგენტი ამ პროცესს აჩქარებს
და ეხმარება README-ს, პრობლემური ადგილებისა და გასაუმჯობესებელი მხარეების პოვნაში.

## PEAS

- **შესრულების საზომი:** პასუხი სწორია და ეყრდნობა რეალურად წაკითხულ ფაილებს. მომხმარებლის კითხვას პასუხობს მინიმალური რაოდენობის tool-ის გამოძახებით.
- **გარემო:** ლოკალური git repository (ფაილებისა და საქაღალდეების სტრუქტურა, კოდი,
  კონფიგურაციის ფაილები).
- **აქტუატორები:** tool-ების გამოძახება (`list_files`, `read_file`) და მომხმარებლისთვის
  ტექსტური პასუხის გაცემა.
- **სენსორები:** მომხმარებლის შეკითხვა და tool-ების შედეგები (საქაღალდის შიგთავსი,
  ფაილის ტექსტი, შეცდომის შეტყობინებები).

## აგენტის ტიპი: goal-based

აგენტს აქვს მკაფიო მიზანი (უპასუხოს მომხმარებლის კითხვას რეალურ მონაცემებზე დაყრდნობით)
და მიზნისკენ მიმავალი ნაბიჯების თანმიმდევრობას თავად ირჩევს. ეს მიდგომა შეესაბამება
გარემოს თვისებებს: რადგან გარემო **ნაწილობრივ დაკვირვებადი** და **თანმიმდევრულია**, ერთი
რეფლექსური წესი არ კმარა და აგენტმა უნდა დაგეგმოს, რა წაიკითხოს შემდეგ.
Simple reflex აგენტი არ გამოდგება, რადგან ერთი მიმდინარე დაკვირვება პასუხისთვის არასაკმარისია.
Utility-based მიდგომა კი ზედმეტია, რადგან ვარიანტების შედარება ან ქულებით შეფასება არ გვჭირდება.

## ხელსაწყოები (tools)

| tool | აღწერა | პარამეტრები | აბრუნებს |
|---|---|---|---|
| `list_files` | ლისტავს საქაღალდეში არსებულ ფაილებსა და საქაღალდეებს | `path` | ჩანაწერების სია ან ERROR |
| `read_file` | კითხულობს ტექსტურ ფაილს | `path`, `max_chars` | ფაილის ტექსტი ან ERROR |
